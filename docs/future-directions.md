# 機能拡張の方針と実装状況

2026-10-16時点の保守版の方針であり、原著者の意図を断定するものではない。
現在の使い方は [README](../README.md)、検証範囲は [test/README.md](../test/README.md) を参照。

## 常時表示の役割

編集に必要な空白文字の存在・種類・個数を、目立ちすぎない表示で識別できるようにする。
本文を変えず、周囲の文字や編集への影響を抑えることを目指す。
配置や使い方の適否は判定しない。例えば改行は明示するが、末尾改行の欠落や
空行の連続を特別扱いしない。

多くのファイルに普通に存在する文字を中心としつつ、言語・用途ごとに必要な文字を
選べるようにする。利用者数や利用頻度の証明は、追加の条件にしない。

## 表示の受動性と許容する制約

次を優先する。

- 本文・変更状態・undoを変えず、読み取り専用バッファでも使える。
- 双方向表示の文字順、結合記号・接続字形を保つ。
- 有効化・無効化・一時停止・復帰で、自分の設定を追加・除去し、
  他機能の変更を巻き戻さない。

論理幅・列位置・タブ位置の維持も目標とする。ただし、`char-width` / `string-width`
の値だけを補正しても、`current-column` や編集コマンドの結果が同じとは限らない。
既存のU+3000では、列計算とカテゴリーによる折り返しに制約があり、
`fill-region` の結果が変わる条件も確認した。
[全角空白の調査](ideographic-space-display.md) に記録した制約を含め、現行方式を許容する。

ピクセル配置や折り返しの完全一致は採用の必須条件にしない。
文字特性の完全な再現を目的とする専用フォントの配布やEmacs本体の改修も、
対応コストに見合わないため行わない。通常のガイドでは制約を簡潔に説明し、
原因を区別した検証条件と反例は調査記録に残す。

より強い不変性を別の選択肢として目指す場合の方式・試作結果・実装規模は
[非置換表示の実現性調査](passive-display-feasibility.md) に記録した。
今回の比較でも、当面は現行設計を維持する。任意の記号・文字列で表示できる自由さと
利便性を重視し、文字合成の列計算上の利点だけでは、表現上の制約と追加の保守負担を
引き受ける根拠には足りないと判断した。文字合成への移行、新たな非置換表示方式、
専用フォントやEmacs本体の改修は進めない。具体的な利用上の支障が確認された場合に、
その条件を改善する対応は引き続き検討する。

## 対象と実装状況

| 対象 | 状況と方針 |
| --- | --- |
| 全角空白（U+3000）・タブ・改行 | 既存機能。公開設定を維持する。 |
| 半角空白（U+0020） | 開発版1.3.0に実装済み。頻出する文字なので、煩わしさと互換性を考慮して既定では無効。 |
| NBSP（U+00A0） | 独自表示は追加せず、標準の `nobreak-char-display` に任せる。 |
| U+202F・U+2800 | 用途が明確な追加候補として優先する。未実装。 |
| EN SPACE・EM SPACE・FIGURE SPACE・THIN SPACE | 組版用空白を識別する追加候補。未実装。 |

半角空白は `jaspace-highlight-spaces` で、無効・faceのみ・文字マーカーを選ぶ。
本文の各空白にoverlayを付け、タブのパディングへの波及を避ける。
設定例は [README](../README.md#半角空白の明示) を参照。

追加候補は全て既定で無効にし、必要な文字だけを選ぶ形を検討する。
U+202F・U+2800のoverlay置換では双方向表示が変わったため、U+0020の方式を一般化せず、
試験で表示順を維持したdisplay table方式を候補とする。
6文字を有限の対応表にまとめる設定案、用途と試験結果は
[追加候補の調査](international-spaces.md) に記録した。採用範囲・公開設定は未確定である。

## 標準機能との分担

Emacs 31.1では `nobreak-char-display` の既定値はtで、NBSPなどを
`nobreak-space` faceで強調する。
[標準の表示仕様](https://www.gnu.org/software/emacs/manual/html_node/emacs/Text-Display.html)
も参照。追加候補の価値は、標準の強調に加えて文字の種類・個数を識別できる点にある。

半角空白のマーカーはwhitespace-modeにもあるが、
[併用調査](whitespace-mode.md) では、対象文字を分けてもtableの保存・復元や幅計算で
干渉することを確認した。このためJaSpace単独でも半角空白を明示できるようにし、
基本機能をwhitespace-modeとの併用が必須となる構成にはしない。
whitespaceのfaceだけを使う暫定的な併用範囲は、同調査に記録した。

## 拡張に含めない機能

- 行末空白、末尾改行の欠落、余分な空行など、位置や個数による適否の判定。
- インデント規約の検査、長すぎる行の警告、改ページ文字の横線表示。
- 空白の整形・自動修正、検査結果による保存の中止。
- 任意のUnicode文字を任意の表示へ差し替える汎用機能。

ゼロ幅文字や結合・書字方向の制御文字も、常時表示の対象にしない。
意図的に必要な文字であり、ゼロ幅のままでよい場合があるためである。
必要ならファイルを開く・保存する・閉じる際の警告や明示的な検査を別に検討するが、
実装の決定ではない。Unicodeの不可視文字を一括して異常扱いしたり、網羅したりする
ことは拡張要件にしない。
